# ShadPanel 1.4.0 — Generator hygiene + docs (current stack)

**Status:** Implementation plan only. This PR does not ship product code.  
**Baseline:** `shadpanel@1.3.1` (`main` at planning time).  
**Stack for 1.4.0:** Next.js 15 + NextAuth v4 + Prisma 6. Templates stay on this stack.  
**Audience:** Kristian (and whoever implements 1.4.0). After reading this file you should know exactly which files change, what the generator will emit, what tests gate CI, and what is explicitly not in 1.4.0.

---

## 1. Goal

Make the **current** CLI generate a project that actually runs after `db init` + `resource`, document that path as the hero, and put Vitest on the CLI so a broken Prisma import fails CI.

1.4.0 is a **hygiene + docs** release on Next 15 / NextAuth v4. It is not a stack upgrade and not Resource 2.0.

### Sequence (locked — do not reopen)

1. **1.4.0** — this plan: generator hygiene + docs on current templates.
2. **Next** — move templates to Next 16 + Better Auth.
3. **Then** — Resource 2.0 (relations, view, policies) on the new stack.

Do **not** hold 1.4.0 for Resource 2.0. Do **not** build `belongsTo` / `hasMany` / M2M widgets on Next 15 / NextAuth.

---

## 2. Locked decisions

| Decision | 1.4.0 meaning |
|---|---|
| Default regenerate is **skip-if-exists** | If a target file already exists, skip it and continue. Never overwrite, even if the user did not edit the file. `--force` overwrites. |
| Prisma 6 is the only generator target | Emit Prisma 6.18 schema + client pin. If the project looks like Prisma 5, **warn** and still emit Prisma 6. Never emit Prisma 5. |
| RBAC later uses `User.roleId` (single) | Do not add Role models, policies, or a `role` string-as-RBAC. Treat `roleId` as a normal scalar. Do not paint into a `User.role` String/enum corner. |
| Relations are Resource 2.0 | `belongsTo` → `FormSelect` and `hasMany`/M2M → view list are **out**. Skip relation object fields. FK scalars (`authorId Int`) stay Int/String widgets. |
| `create-shadpanel-next@0.1.0` | Deprecate and redirect to `shadpanel init`. A **docs note** is required in 1.4.0. Optional: a runtime deprecation warning in that package's CLI. |
| No hardcoded passwords in **new** files | Seed, `lib/prisma.ts`, schema, and new docs must not add `admin123` or real secrets. Existing demo credentials in auth templates stay unless those files are already being rewritten for another 1.4.0 reason. |

## 3. Current-state audit (verified in 1.3.1)

These are repo facts, not assumptions.

### 3.1 `resource` imports `@/lib/prisma` but never emits it

`cli/commands/resource.ts` writes `actions.ts` with:

```ts
import prisma from '@/lib/prisma'
```

`init` copies `lib/` via `copyLibUtils` (`cli/utils/files.ts`). The published `lib/` directory contains **only** `lib/utils.ts` (`cn`). There is no `lib/prisma.ts` in the package, templates, or generator output.

A generated resource therefore has a **broken import** on first generate. This is the primary generator bug.

### 3.2 `db init` writes `schema.prisma.template`, not `schema.prisma`

`cli/commands/prisma.ts` `db init`:

- Creates `prisma/schema.prisma.template` with `{{DATABASE_DRIVER}}` / `{{DATABASE_URL}}` placeholders.
- Then looks for `prisma/schema.prisma`, does not find it, warns, and skips `prisma generate`.
- Next-step copy tells the user to edit `.template`, then `schema.prisma`, then run `shadpanel db migrate` (no subcommand).

`cli/utils/db.ts` `generatePrismaSchema()` reads the **user project's** `.template`, interpolates a **literal** `DATABASE_URL` into `schema.prisma`, and writes it. `db generate` always runs that path first, so it can **overwrite** a user-edited `schema.prisma`.

`.template` must live only inside the CLI package (e.g. `templates/prisma/`), never as a user-facing project file.

### 3.3 Scalar widgets: create/edit only emit `FormInput` / `FormCheckbox`

Verified mapping in the **written** create/edit pages (`resource.ts`):

| Prisma type | What is actually written |
|---|---|
| `Boolean` | `FormCheckbox` |
| `Int` / `Float` / `Decimal` | `FormInput` `numeric` |
| everything else (`String`, `DateTime`, **enum**, `Json`, `Bytes`) | `FormInput` `type="text"` (or `email` if the name contains `email`) |

`FormSelect` and `FormDatePicker` exist only in a `formContent` string that is **never pushed** to `filesToWrite`. Dead code. `FormDateTimePicker` and `FormSelect` already exist in `components/ui/form-builder` and are re-exported from `@/components/ui`.

Relation object fields (`isRelation`) are already skipped. Keep that.

### 3.4 No seed stub

`db seed` runs `npx prisma db seed` and, on failure, says “Make sure you have a `prisma.seed` script in package.json”. `db init` does not write `prisma/seed.ts` and does not add `package.json` `prisma.seed`. Generated `package.json` (`templates/config/package.json.template`) has migrate/push/generate scripts only.

### 3.5 Skip vs fail

`resource --force` exists. Without it, an existing file **exits 4** (`File exists: … (use --force to overwrite)`). Locked default is **skip-if-exists and continue**, not fail-the-run.

`init` merge and `copyUIComponents` / `copyLibUtils` already skip existing files (`overwrite: false`). Align `resource` (and new emits) with that.

### 3.6 Docs vs templates

| Claim | Reality in 1.3.1 |
|---|---|
| README “Quick Start” hero | `shadpanel init` + `npx create-shadpanel-next`. **`resource` is not mentioned anywhere in README.** |
| README “This will” after `db init` | First list is db-init bullets; a second “This will” list is leftover **init** feature bullets (Next 15, NextAuth, form builder). Copy/paste error. |
| README Requirements / Tech Stack | **Next.js 14** / React 18. Templates are **Next `^15.0.0`**, React `^19.0.0`, NextAuth `^4.24.0` (`templates/config/package.json.template`). |
| README migrate syntax | `shadpanel db migrate make \| run \| status` — **matches** the CLI. Keep this. |
| `db init` success copy | `shadpanel db migrate` (bare) — CLI treats bare `migrate` as `run`, not `make`. Confusing. |
| `db pull` success copy | `shadpanel db:generate` (colon). Real command is `shadpanel db generate`. |
| CHANGELOG | **Missing.** 1.4.0 must add `CHANGELOG.md` starting at 1.4.0 (do not backfill 1.3.1). |
| Root `cli.cjs` | Dead leftover scaffolder that writes **Next `^14.0.0` / React 18**. Not the `bin` entry (`dist/cli.js`). Delete or stop shipping so nothing claims Next 14. |
| `package.json` `"test"` | `echo "Error: no test specified" && exit 1`. No Vitest, no `.github/workflows`. |
| `create-shadpanel-next` README | Stack versions are closer (Next 15.5.4, NextAuth v4) but still documents `npx create-shadpanel-next` as the path and **hardcodes demo password `admin123`**. |

No docs in this repo claim NextAuth v5. Do not introduce that claim.

### 3.7 Prisma pin already exists

`db init` installs `@prisma/client@6.18.0` and `prisma@6.18.0`. Keep 6.18 as the 1.4.0 pin. Do not add a Prisma 5 code path.

### 3.8 Auth demo credentials (pre-existing)

Hardcoded `admin@example.com` / `admin123` live in:

- `templates/auth/app/api/auth/[...nextauth]/route.ts`
- `templates/auth/components/login-form.tsx`
- `components/login-form.tsx`
- `packages/create-shadpanel-next` copies of the above + its README

These are **existing**. 1.4.0 does not need to rip them out unless a file is already rewritten. **New** files must not add passwords.

### 3.9 Other generator smells (in scope only if cheap)

- List page only renders the first **two** non-id scalar columns. Not a must-fix unless widgets work lands next to it.
- Menu inject is naive: always imports `Users`, regex-inserts into `navMain`, can duplicate items. 1.4.0: skip-if-item-exists; do not redesign the menu system.
- `formContent` dead block + unused `/api/${folderName}` fetch. Delete when resource emit is cleaned up.
- `.gitignore` lists `packages/` even though `packages/create-shadpanel-next/**` is tracked. Risk when editing that package — `git add -f` if needed.

## 4. What 1.4.0 will change

### 4.1 Extract testable generator pieces

`resource.ts` is a 665-line command with inline parser + string templates. Split so Vitest can fail a bad emit without spawning the full CLI for every case.

| New module | Responsibility |
|---|---|
| `cli/generate/parse-prisma.ts` | Move `parsePrismaSchema`, `SCALAR_TYPES`, `Field`. Keep current heuristics (enums, `@id`, `@default`, relation = not scalar and not enum). |
| `cli/generate/prisma5.ts` | Detect “looks like Prisma 5”; return warning strings. Never emit a Prisma 5 schema. |
| `cli/generate/widgets.ts` | `mapScalarWidget(field, enums)` → widget kind + JSX snippet + imports + initial value. |
| `cli/generate/write-policy.ts` | `writeFile({ path, content, force, dryRun })` → `written` \| `skipped` \| `overwritten`. Skip-if-exists unless `force`. |
| `cli/generate/emit-prisma-client.ts` | Contents of user `lib/prisma.ts` (PrismaClient singleton, default export `prisma`). |
| `cli/generate/emit-schema.ts` | Prisma 6 schema body: `provider` from driver, `url = env("DATABASE_URL")`, `generator client { provider = "prisma-client-js" }`, commented example model. No interpolated credentials. |
| `cli/generate/emit-seed.ts` | Stub `prisma/seed.ts` with no sample users/passwords. |
| `cli/generate/emit-resource.ts` | Build the four resource files + optional menu patch from parsed model. **Delete** the unused `formContent` / REST `fetch` block. |
| `cli/commands/resource.ts` | Thin commander wrapper: resolve paths, call parser + emitters + write policy, print created/skipped/overwritten. |

`cli/commands/prisma.ts` and `cli/utils/db.ts` call `emit-schema` / `emit-prisma-client` / `emit-seed` instead of inlining another template.

### 4.2 Emit `lib/prisma.ts`

Emit on **`db init`** and on **`resource`** (whichever runs first). Skip-if-exists.

Required shape (default export must match `import prisma from '@/lib/prisma'`):

```ts
import { PrismaClient } from "@prisma/client"

const globalForPrisma = globalThis as unknown as { prisma?: PrismaClient }

export const prisma = globalForPrisma.prisma ?? new PrismaClient()

if (process.env.NODE_ENV !== "production") {
  globalForPrisma.prisma = prisma
}

export default prisma
```

No connection URL, no password, no datasource branching.

If `resource` runs and `lib/prisma.ts` is missing, emit it and log that it was created. Do not require the user to re-run `db init`.

### 4.3 `db init` writes `prisma/schema.prisma`

- Write **`prisma/schema.prisma`** from the **CLI-package** template (`templates/prisma/schema.prisma.template`).
- Do **not** write `prisma/schema.prisma.template` into the user project.
- Schema must be Prisma 6:

```prisma
datasource db {
  provider = "postgresql" // or mysql | sqlite | mongodb from the prompt
  url      = env("DATABASE_URL")
}

generator client {
  provider = "prisma-client-js"
}

// Add your models here
```

- Still write/append `.env` + `.env.example` as today (`cli/utils/db-prompts.ts`).
- Install Prisma **6.18.0** when requested (keep current pin).
- If `schema.prisma` now exists, run `prisma generate`.
- Also emit `lib/prisma.ts` and the seed stub (4.5).

**Prisma 5 warning (do not emit Prisma 5):**

Warn (stderr + logger.warn), then continue with Prisma 6 emit, when any of:

1. `package.json` `dependencies`/`devDependencies` `prisma` or `@prisma/client` has major `5`.
2. Existing `schema.prisma` contains Prisma-5-era `previewFeatures` that 6.18 does not want us to re-emit (`jsonProtocol`, `filterJson`, `interactiveTransactions`, `referentialIntegrity` as a preview). Maintain the list in `cli/generate/prisma5.ts`.
3. Existing file is `schema.prisma.template` with `{{DATABASE_URL}}` placeholders (1.3.1 leftover).

If `schema.prisma` is missing but `schema.prisma.template` exists: one-time migrate — write `schema.prisma` from the **CLI** Prisma 6 template (not by interpolating the old user `.template` URL), warn that `.template` is obsolete, do not keep writing `.template`.

**`db generate` behavior change:** only run `prisma generate` (client). Do **not** regenerate `schema.prisma` from a template. Optional `--regenerate` on `db push` today calls `generatePrismaSchema()`; remove user-project-template regeneration. If we keep a flag, it must re-copy from the **CLI package** template and still honor skip-if-exists unless `--force`.

Update next-step copy:

```
1. Edit .env with real credentials
2. Edit prisma/schema.prisma (add models)
3. shadpanel db migrate make <name>
4. shadpanel db migrate run
5. shadpanel resource <Model>
```

Fix `db pull` help: `shadpanel db generate` (space, not colon).

### 4.4 Scalar widget map (create + edit, one function)

Skip: `isId`, `isRelation`, and list types (`[]`, already classified as relation by the parser).

| Prisma | Widget | Initial value | Notes |
|---|---|---|---|
| `String` | `FormInput` | `''` | `type="email"` if name includes `email`; `type="password"` if name includes `password` (no default password value). |
| `Int` / `Float` / `Decimal` | `FormInput` `numeric` | `''` | Same as today. |
| `Boolean` | `FormCheckbox` | `false` | Same as today. |
| `DateTime` | `FormDateTimePicker` | `''` | Component already uses `datetime-local`. Not `FormDatePicker` (date-only). |
| enum | `FormSelect` | `@default(...)` stripped of `()` / first enum value / `''` | `options={[{ label, value }]}` from parsed enum. |
| `Json` | `FormTextarea` | `''` | Allowed extra; not required. |
| `Bytes` | skip field + comment | — | No widget in the library. |

`required` on the widget when the Prisma field is required and has no `@default`.

Create/edit imports must include only widgets that appear (`FormDateTimePicker`, `FormSelect`, …).

**Do not** map relation objects or turn FK scalars into `FormSelect`. `authorId` / `roleId` stay numeric/string inputs. That leaves Resource 2.0 and RBAC (`User.roleId`) unconstrained.

List page: keep current two-column slice unless a one-line change to “all non-relation scalars” is free during the emit cleanup. Not a release blocker.

### 4.5 Seed stub

On `db init` (skip-if-exists):

**`prisma/seed.ts`** — empty `main()`, `PrismaClient` connect/disconnect, no User rows, no passwords.

**`package.json`:**

```json
"prisma": {
  "seed": "npx tsx prisma/seed.ts"
}
```

Add `tsx` as a **devDependency** of the generated app when `db init` installs Prisma (same pin style as prisma: current latest 4.x is fine; do not add a password). If `package.json` already has `prisma.seed`, skip.

`db seed` copy can then say “edit `prisma/seed.ts`” instead of only “add prisma.seed”.

### 4.6 Write policy (skip-if-exists)

Apply to every file the CLI creates in 1.4.0:

- resource: `actions.ts`, `page.tsx`, `create/page.tsx`, `edit/[id]/page.tsx`
- `lib/prisma.ts`
- `prisma/schema.prisma`
- `prisma/seed.ts`
- menu item insert (skip if URL already present)

Behavior:

| State | Default | `--force` |
|---|---|---|
| file missing | write, log created | write |
| file exists | skip, log skipped, **continue** | overwrite, log overwritten |

Do **not** `process.exit(4)` because one file exists. Exit non-zero only for missing schema, missing model, or I/O errors.

`--dry-run` prints would-create / would-skip / would-overwrite and writes nothing.

## 6. Test plan

Framework: **Vitest**, Node environment, `npm test` = `vitest run`.

### 6.1 Unit — broken Prisma import fails CI

- `emit-resource` for a one-field model snapshot/`includes` `import prisma from '@/lib/prisma'` (or the agreed equivalent).
- `emit-prisma-client` snapshot includes `PrismaClient` and `export default prisma`.
- A helper `assertResolvableImport(specifier, emittedFiles)` used by both tests: if `actions.ts` imports `@/lib/prisma` and the emit set has no `lib/prisma.ts`, **the test fails**.
- Regression: a fixture that only emits `actions.ts` (no client) must fail this helper — lock the helper itself with a negative test.

### 6.2 Unit — widgets

Table-driven cases on a tiny schema:

```prisma
enum Status { DRAFT PUBLISHED }
model Post {
  id        Int      @id @default(autoincrement())
  title     String
  views     Int
  published Boolean  @default(false)
  publishedAt DateTime?
  status    Status
  author    User     @relation(...)
  authorId  Int
}
```

Expect: `title`→FormInput, `views`→FormInput numeric, `published`→FormCheckbox, `publishedAt`→FormDateTimePicker, `status`→FormSelect with DRAFT/PUBLISHED, `author` skipped, `authorId`→FormInput numeric (not FormSelect), `id` skipped.

### 6.3 Unit — write policy

Temp dir: existing file + default write → skipped, content unchanged. `--force` → overwritten. Missing file → created.

### 6.4 Unit — schema emit / Prisma 5

- `emit-schema` output contains `url = env("DATABASE_URL")`, does **not** contain `{{DATABASE_URL}}` or a `mysql://…:password@` literal, does **not** write a `.template` path.
- `looksLikePrisma5({ packageJson, schema })` true for `prisma: "5.22.0"` and for `previewFeatures = ["jsonProtocol"]`; false for a clean 6.18 schema.
- Emit function never returns a Prisma 5 previewFeatures block.

### 6.5 Unit — seed

- Stub has no `password`, `admin123`, or `admin@example.com`.
- `package.json` patch adds `prisma.seed` without clobbering other keys.

### 6.6 Fixture — init + one-model resource → resolvable import graph

Not a full Next build (too heavy / needs a real DB). Static graph:

1. Temp dir.
2. Seed a minimal “generated app” surface: `tsconfig` paths `@/*` → `./*`, empty `components/ui` barrel **or** copy the real `components/ui/index.ts` + enough stubs that imports parse.
3. Write a one-model `prisma/schema.prisma` (Prisma 6).
4. Run `emit-schema` / `emit-prisma-client` / `emit-seed` / `emit-resource` (functions, not `exec` of the whole CLI — faster and deterministic). Optionally one integration test that `tsx cli/index.ts resource Post --path <tmp> --skip-menu` against a pre-written schema.
5. Collect every `from '…'` / `from "…"` in emitted `.ts`/`.tsx`.
6. Resolve:
   - `@/x` → `<tmp>/x` with `.ts` / `.tsx` / `/index.ts`.
   - relative imports similarly.
   - `next/*`, `react`, `@prisma/client`, `lucide-react`, `sonner` = allowed externals.
7. **Fail** if any `@/` or relative import has no file.

This is the test that would have caught 1.3.1 (`@/lib/prisma` missing).

Optional extra: `tsc --noEmit` on the temp tree with `skipLibCheck` after writing a tiny `components/ui` stub. Nice, not required if the graph walk is strict.

### 6.7 Docs smoke (cheap)

Grep test or a `docs/stack.test.ts`:

- README must not match `Next.js 14` / `Next 14` / `NextAuth v5` / `NextAuth.js v5`.
- README must contain `shadpanel resource` above the first `create-shadpanel-next` (or contain `deprecated` on that line).
- README must contain `shadpanel db migrate make` and must not contain `shadpanel db:generate`.

### 6.8 Out of test scope for 1.4.0

Browser E2E, real MySQL, `prisma migrate` against a live DB, Better Auth, Next 16.

## 8. Risks

| Risk | Why it matters | Mitigation |
|---|---|---|
| Users already have `prisma/schema.prisma.template` from 1.3.1 | They will follow old next-step copy; `db generate` today overwrites `schema.prisma`. | One-time warn + migrate; `db generate` stops rewriting schema; README says edit `schema.prisma` only. |
| Skip-if-exists vs today’s fail-if-exists | Regenerating a resource will leave stale create/edit pages unless `--force`. | Document in README and command help. Log skipped paths. This is the locked default. |
| `db generate` no longer builds schema from template | Anyone relying on `{{DATABASE_URL}}` interpolation loses that path. | Intended. Schema uses `env("DATABASE_URL")`. Call out in CHANGELOG as breaking CLI behavior. |
| Interpolated URL in 1.3.1 schemas | Old `generatePrismaSchema()` wrote credentials into `schema.prisma`. | New emit never does that. Do not rewrite existing user schemas without `--force`. |
| FK scalars look like “missing relation widgets” | `authorId` is an Int input. Users may file bugs. | README: relations are skipped in 1.4.0; Resource 2.0 later. Tests lock `authorId` ≠ FormSelect. |
| `User.role` String in dummy types | `templates/demo/types/user.ts` has `role?: string` (DummyJSON). | Do not generate User RBAC from that. Future RBAC is `User.roleId`. Do not add a Role picker. |
| `create-shadpanel-next` is a full template fork | Docs-only deprecation leaves a stale npm package that still scaffolds. | Docs + optional CLI warning. Do not spend 1.4.0 syncing that tree. |
| `packages/` in `.gitignore` | Easy to think create-shadpanel-next changes are untracked. | `git add -f` if needed; confirm `git ls-files`. |
| Fixture test too heavy | Full `init` + npm install + next build will flake. | Test emitters + import graph, not a production Next compile. |
| Auth `admin123` remains | Looks like 1.4.0 “still ships passwords”. | CHANGELOG / plan: pre-existing demo login, not new. New files scanned for `admin123`. |
| Pin 6.18.0 vs latest 6.x | Drift. | Keep 6.18.0 unless it is unpublished; do not jump to Prisma 7. |

## 9. Success criteria

Kristian (or CI) can do the following on a clean machine after 1.4.0:

1. `npx shadpanel@1.4.0 init my-app --yes --skip-install` (or equivalent) gets a Next **15** / NextAuth **v4** tree.
2. `shadpanel db init` in that app writes **`prisma/schema.prisma`** (Prisma 6, `env("DATABASE_URL")`), **`lib/prisma.ts`**, **`prisma/seed.ts`**, and `package.json` `prisma.seed`. No `schema.prisma.template` in the app.
3. Add a one-model schema (String, Int, Boolean, DateTime, enum). `shadpanel resource <Model>` writes list/create/edit/actions that import `@/lib/prisma` **and** that file exists.
4. Create/edit use FormInput / FormInput numeric / FormCheckbox / FormDateTimePicker / FormSelect. Relation objects omitted. `roleId`/`authorId` stay scalars.
5. Re-run `resource` without `--force`: existing files skipped, process exits 0.
6. `--force` overwrites.
7. `npm test` in this repo fails if the Prisma import is emitted without `lib/prisma.ts`.
8. README opens with `shadpanel resource`. No Next 14, no NextAuth v5. Migrate docs use `make` / `run` / `status`. CHANGELOG starts at 1.4.0. `create-shadpanel-next` is documented as deprecated.
